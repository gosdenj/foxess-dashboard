# Release 2026-10-27.5 — swipe the deck

The dashboard is on a touch screen, so a sideways swipe turns the deck:
left for the next slide, right for the one before.

## What it does

```
   swipe left  ──►  power  →  usage  →  weather  →  power
   swipe right ──►  power  ←  usage  ←  weather  ←  power
```

The rotation wraps round at both ends, so the order is the same whichever
way it is entered from. The slide arrives from the side it was swiped
from — the next one comes in from the right, the one before from the
left — so the gesture and the animation agree with each other.

## The gesture is measured, not guessed

A swipe has to travel at least **60 pixels sideways**, and further sideways
than up and down. Anything less is a tap, and a tap is left as a tap.

A swipe that **starts on a button** is left alone, so the gear in the
corner still opens the settings. Pointer events are used rather than touch
events, so a mouse drag does the same thing — which is how it can be tried
out on a desktop before it is used on the panel.

The browser is told to leave the swipe alone (`touch-action: none`): the
dashboard is one screen and never scrolls, so a swipe belongs to the page.

## It answers straight away

The slide is shown **immediately**, rather than waiting for the server's
answer to come round the loop. The event stream is checked once a second,
so waiting for it would make the gesture feel like it had been ignored.
The server has the last word: if it says something different, the slide
changes again.

The server is asked to step the rotation:

```
POST /api/slide   {"step": 1}     the next slide
POST /api/slide   {"step": -1}    the one before
POST /api/slide   {"name": "..."} a named slide, as before
```

## A slide you chose is not taken away

A slide the user has swiped to gets the **full rotation interval** — it is
not yanked away a moment later by the rotation that was already running.
The rotation is told that the slide was moved by hand, and starts its
clock again.

## Testing

- 412 tests (was 392): 19 for the swipe — the rotation's step in both
  directions and wrapping, the endpoint, and the gesture in the page.
- The swipe was checked in a real browser: left and right, wrapping round
  at both ends, a short drag (not a swipe), a vertical drag (not a swipe),
  and a swipe that starts on the gear (left alone).
- The animation was checked too: a swipe left brings the slide in from the
  right, a swipe right from the left.
- The layout check: all 48 viewports fit on one screen, no scrolling.
