# Release 2026-10-26.8 — the fit that was not happening

The weather slide was rendering, but the solar forecast was not: it showed
the sun in kWh/m² and never the yield in kWh, because the array had never
been fitted. Three things were wrong.

## 1. The test worked on settings that were never saved

**Test the forecast** fetched the forecast with the values in the form,
which is right for trying things out — but it never wrote them down. So
the test said "Portsmouth, England: Overcast, 16.7 °C" while the slide
sat there with no place set at all, saying nothing.

It is now **Save and test the forecast**: it saves what was tested, and
only what actually changed, and then says so. The Octopus button has
worked that way all along.

## 2. The fit needed the Open API, and did not have to

The yield came from the FoxESS production report, which needs the Open
API key. Without it the fit had nothing to work with.

But the **live feed carries the solar power** — it is right there in the
WebSocket, every five seconds — and integrating it over a day gives that
day's yield. The history already does exactly that for the usage chart,
so it now does it for the fit as well:

```
HalfHourHistory.daily_pv()  →  {2026-10-25: 8.42, 2026-10-26: 1.13, …}
```

The inverter's own register still wins wherever both have it. The fit now
says which source it used — *the inverter's report*, *the live feed*, or
both — in the Detected table.

The history keeps 21 days now, rather than 7, so the fit has a window.

## 3. The fit waited up to fifteen minutes for the report

The weather worker polled every fifteen minutes, so when the inverter's
daily report arrived at second zero the fit did not catch up until the
next poll. The report now wakes the weather worker, and so does a change
to the weather settings.

## 4. And the settings save could fail with a 500

A plain function stored on a class becomes a **bound method** when it is
reached through an instance — so the callback that re-wires the
connections was handed the request handler as well, and complained that
it had been given two arguments instead of one. The settings page got a
500 and the dashboard never heard about the change.

A bound method (which is what the real dashboard passes) was fine, which
is why this only showed up in the demo. `handler_class()` now wraps a
plain function in `staticmethod`, and there is a test that goes through
an **instance** — the earlier version of the test read the callback off
the class, which is exactly where the bug does not show.

## When it still cannot be fitted, it says why

The slide and the Detected table now carry the reason rather than a
vague "not enough days yet":

- *the inverter has not reported yet - the Open API key may not be set*
- *the inverter's daily report failed: …*
- *the inverter has not reported a daily solar yield yet*

## The cross-check

**Array size (kWp)** is a new, optional setting. It is not needed — the
dashboard works the size out for itself — but if you know it, the fit can
be checked against it:

```
Your array is    5.50 kWp - the fit says 5.53 kWp (they agree)
Performance ratio   0.85 - measured, not assumed
```

The performance ratio is normally an assumption. With a known array size
it becomes a **measurement** — and that is the more interesting number
anyway, because it says how well the array actually performs.

## The demo

The demo pretends to have a 5.5 kWp array, and the pretend array only
covers the days that have actually happened — a forecast is not evidence.
306 tests (was 300).
