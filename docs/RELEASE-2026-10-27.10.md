# Release 2026-10-27.10 — the README is checked against the code

A README is the first thing anybody reads, and the way it goes wrong is
always the same: it describes a variable, a file or a default that has since
moved on. This release puts the README right, and adds the test that keeps it
that way.

## What was wrong

**`FOXESS_API_INTERVAL` was documented, and nothing read it.** It appeared in
the Configuration table as though it set the Open API poll interval. It does
not: the interval is the `api_interval` setting, on the settings page under
**Data sources**, and it lives in the settings file like everything else. The
variable was never in the seeding map and never read from the environment, so
setting it did nothing at all. The row is gone, and the README now says where
the interval really lives.

**The example config bound to localhost while the code binds to everything.**
`config.example.json` said `"host": "127.0.0.1"`; the default in the code is
`0.0.0.0`. So the README's own quick start — copy the example, run it — gave
a server that only answered on the machine it ran on, and the Pi screens
could not reach it. The example now matches the code.

**The diagram was in the wrong place.** The README said the two styles were
switched from **Display → Diagram**. They are switched from **Power flow
diagram**, under a control called **Style** — and the README contradicted
itself two pages later, where the Screenshots section had it right.

**The file tree was a snapshot of an earlier repository.** It listed eight of
the fifteen test files, and omitted `foxess/sun.py`, `flow_direction_check.py`
and the Portainer guide. It is now the whole tree.

**The server was still described as running on the Pi.** It runs in a
container on the host; the Pi is a display terminal. The architecture
diagrams in the README and in `display/README.md` said otherwise.

**Three numbers in the layout tables were stale.** Measured at 800×480 with a
real browser: the flow values are 27 px, the rings values 25 px and the hub's
level 31 px. The README said 26, 21 and 27.

## The test

`tests/test_readme.py` reads the README and checks it against the code:

- every variable in the Configuration table is one the code actually reads
- `FOXESS_DASHBOARD_CONFIG` is looked up in the order the README says
- the example config agrees with the code's defaults, and holds no secrets
- every Python file in the repository is listed in the file tree
- both guides are linked

Seven tests. The tree test is the one that earns its keep: it fails the build
the moment a module is added and the README is not updated.

## Also

- The front end fell back to the **flow** diagram when the settings had not
  arrived yet, although **rings** is the default everywhere else. It now
  falls back to rings, and `tests/test_diagram.py` checks that the fallback
  and the configured default agree.
- The Tests section was one long paragraph. It is three now.

## Testing

- 471 tests (was 464): six for the README, one for the diagram fallback. The
  only failure is the pre-existing one — `test_esp32_render` needs Pillow,
  which is not installed.
- The layout figures were measured in Chrome at 800×480 against the live
  dashboard, in both diagram styles.
