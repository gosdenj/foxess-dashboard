> **Fixed in this build:** the Mini could not be read.
>
> There were two problems.  The first was authentication: the session
> token was being asked for with the account's email and password, which
> Octopus rejects with a bare "Invalid data." — that route wants a

> Octopus says the Octopus Care feature is no longer supported — and it
> now answers "Account is not currently supported."  The device is now
> found through the meter itself
> (`smartImportElectricityMeter.deviceId`), which is the modern way and
> the one the Home Assistant integration uses.
>
> Both fixes were needed; the error you saw was the second one.  The first
> version asked Octopus for a session token with the account's email and
> password, and Octopus rejected that with a bare "Invalid data."  The
> GraphQL schema says otherwise — the token can be had with the **API
> key** on its own, which is both easier and what the dashboard already
> had.  The email and password are now a fallback, and the error

## What this adds

**Live figures from the Octopus Mini.**

The Mini reads the meter itself, so its numbers are live rather than a
day or two behind like the half-hourly readings.  The dashboard now uses
them.

### How it gets the data

The Mini's data only comes from Octopus's **GraphQL** API, and that one
wants the account's **email and password** rather than the API key.  So
the settings page has two more fields, and the Mini is entirely optional.

Three calls, all standard library:

1. `obtainKrakenToken` — a session token, from the email and password
2. the account's meter — `smartImportElectricityMeter.deviceId` — which is
   the smart meter's own id, the one the telemetry is asked for
3. `smartMeterTelemetry` — the readings, grouped ten seconds, one minute,
   five minutes, half hourly or hourly

### What the schema gives us

| Field | What it is |
|---|---|
| `demand` | the power being used right now, in W |
| `consumption` | the meter's running total of energy imported, in Wh |
| `export` | the meter's running total of energy exported, in Wh |
| `consumptionDelta` | the energy in that period, in Wh |
| `costDeltaWithTax` | the cost of that energy, in pence including VAT |

The counters are cumulative, so today's energy is the difference between
the counter now and the counter at local midnight.  The query starts an
hour early so the counter just before midnight is caught.

### On the Usage slide

- **● 0.42 kW now** — the meter's live reading, in the panel header
- **Imported** and **Exported** — today's figures, from the meter's own
  counters rather than the inverter's estimate
- **Cost today** — what the meter says you have spent, counted by
  Octopus itself

The export direction comes from the meter's counter, which the
half-hourly API does not give you unless the account has a separate
export meter point.

## Careful things

- **The rate limit.**  Octopus allows about a hundred calls an hour for
  the whole account, shared with the Octopus app.  The Mini is polled
  every two minutes (two calls) and the half-hourly readings every five
  minutes, which is about 66 calls an hour.
- **The token is kept** between polls and only fetched again when the
  credentials change, so the rate limit is not spent on logins.
- **An expired token** is refreshed once and the call retried — but a
  real error is not retried for ever.
- **Today means the local day**, not the UTC one: the counters are read
  from midnight UK time.
- **The Mini is optional.**  Without it the slide falls back to the
  half-hourly readings and the inverter's daily register, exactly as
  before.
- **The password is a secret** — masked in the API, stored with the
  other secrets, and only ever used to get a token.
- **The API key gets the token**, so nothing extra has to be entered.
  The login route is rate-limited by Octopus, so it is only used if the
  API key is not accepted.
- **A failure backs off** — the poll interval doubles, up to fifteen
  minutes, so a broken Mini cannot eat the account's call allowance.
- **The errors are useful now**: Octopus's "Invalid data." is replaced
  with what it actually says, such as "Authentication failed."
- **The retired query is gone**, so the "not currently supported" error
  cannot come back.

# Build 2026-10-26.4 — the Mini's reply is parsed properly

The device id query was working, but the reply was being read wrongly:
Octopus returned a **list** where the schema says a single object, and
the parser asked for `.get()` on it.

Rather than guess which field was the list, the parser now walks
everything as though it might be a list or a single item, and when it
still cannot find the smart meter the error says **what the reply
looked like** — the shape of the JSON, not the data in it, so nothing of
the account's details is printed.  The next test will therefore show
exactly what came back.

The same tolerance was applied to the account lookup that finds the
meter point, which walks the same path.

# Build 2026-10-26.6 — the usage chart shows the grid

The chart was showing the **house's** use, which is the wrong thing for
an Octopus slide.  Three things were wrong with it:

1. **It plotted the house, not the grid.**  The house's use does not
   change when the battery covers it, so a chart of it looks identical
   whether you are running on solar or pulling from the grid — and it
   never shows the grid import.  The chart now shows the **import above
   the line and the export below it**.

2. **The hourly fallback was drawn as half-hourly.**  When the
   dashboard has only just started, the inverter's hourly report fills
   in — but an hour's energy is twice a half hour's, so those bars were
   drawn at double the size and labelled "kWh per half hour".  The
   grain is now stated in the payload and the scale follows it.

3. **The meter's readings were not being used.**  The Mini's own
   half-hourly readings are what crossed the grid boundary, so where
   they exist they now replace the inverter's estimate of the same
   thing.

Also fixed: **Self-used** in the Today row was
`(house − grid in) / house`, which collapses to **zero** whenever the
battery is charged from the grid — the opposite of the truth.  It is now
the share of the solar that stayed on site.

And the meter's per-period energy now comes from the `consumptionDelta`
the meter reports, which is the period *after* each reading, so the bars
line up with the times they happened.

# Build 2026-10-26.6 — checking the chart is not telling a lie

A request to check the usage chart for false data turned up a real bug
and a way to prove the numbers are right.

## The bug

When the dashboard starts, the local history is empty for the first few
hours, and the chart falls back to the inverter's **hourly** report. That
fallback filled in the house and left the grid at **zero** — so the chart
drew a flat, empty grid under a legend that said "grid import". Every
channel now comes from the report.

## The proof

The Mini's readings are now checked against the Octopus app:

```
mini: 4.21 kWh imported today, the biggest half hour 2.71 kWh at 02:00
  against the inverter: 4.08 kWh (difference +0.13 kWh)
```

The biggest half hour is the largest amount of energy the meter saw cross
the grid boundary in one half hour, and the second line compares the
meter's day total with the inverter's count of the same grid. If the
first does not match the Octopus app, the chart is wrong.

## Also

- The chart's title says **where the numbers came from** — the Octopus
  meter or the inverter — so it can never be mistaken for something it
  is not.
- The scale says **peak import** or **peak export**, not just "peak".
- A day that only has part of its readings is marked as partial, in the
  panel and in the test output.
- The meter's own per-period figure is used where the meter gives one,
  rather than a difference of running totals, which lands the energy in
  the wrong half hour.
