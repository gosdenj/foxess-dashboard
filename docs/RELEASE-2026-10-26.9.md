# Release 2026-10-26.9 — the units that were not carried through

The wind speed set in the settings was not the wind speed on the Weather
slide. With **Miles per hour** chosen, the forecast was fetched in miles
per hour — and then labelled *km/h*.

## Why

The weather service does not echo the unit back the way it was asked
for. It writes its units in its own way:

```
asked for:  mph          the reply says:  mp/h
asked for:  ms           the reply says:  m/s
asked for:  fahrenheit   the reply says:  °F
```

The dashboard read the unit out of the reply, compared it against a table
of the names it had asked for, and did not find it. Anything it did not
recognise fell back to `km/h`, and to `°C`.

So the numbers were right and the labels were wrong — and for anyone who
had chosen Fahrenheit, the numbers were in °F and the slide said °C.

## What is done now

The unit is taken from the **settings** and carried the whole way
through — through the fetch, through the reply, and into the label on
the slide. The reply is only read when there is no setting to read, and
it is now understood whatever way it is spelled.

Every reading on the slide is labelled with it, including the ones that
had the unit written into them:

| | Before | Now |
|---|---|---|
| The temperature | `17°` | `17°C` |
| Feels like | `16°` | `16°C` |
| The day's high and low | `17°` / `11°` | `17°C` / `11°C` |
| The wind | `20 km/h` | `20 mph` |

## The demo converts its numbers

The demo has no forecast to fetch, so it makes one up — and the made-up
numbers were in km/h and °C whatever the settings said. They are now
converted, so the demo shows the same units the real forecast would.

## The slide has no units written into it

There is a test that says so: no reading on the slide may carry a unit
typed into the code, because a unit in the code is a unit that ignores
the settings.

325 tests (was 313).
