# Release 2026-11-02.1 — the forecast survives a busy service

Open-Meteo is sometimes too busy to answer. It says so with a 503 and
`"reason":"The service is overloaded"`, and until now the dashboard's
answer to that was to empty itself: the temperature became a dash, the
week ahead went blank, the solar forecast went with it, and the slide
showed the raw error instead.

Nothing was cached, so there was nothing to fall back on.

Now the last good reply is kept, and the slide shows it — **with its age
on it** — for as long as it is worth showing.

## What was there before

- The weather was fetched every fifteen minutes (96 calls a day) and the
  parsed result kept **in memory only**. A restart lost it.
- On any failure the payload was replaced by
  `{"error": ..., "days": [], "current": {}, "solar": {}}` — so the last
  good forecast was *thrown away*, not kept.
- Open-Meteo sends no `ETag`, no `Cache-Control` and no `Expires` — I
  checked the live response headers — so there was nothing to
  revalidate against. Any caching had to be ours.

## What there is now

**The reply is kept on disk.** `config-weather.json`, next to the
settings and the inverter's own history, in the same mounted volume, so
it survives a restart and a redeploy. It is 27 KB, it is written
atomically, and it is mode 0600 — it holds the plant's coordinates. The
demo keeps its cache in memory instead, exactly as it keeps its history:
it is made up, and it must never be written over the real one.

**A failure falls back to it.** The cached reply is re-parsed and the
solar calibration is worked out again — that part depends on the
inverter's own yield, not on the weather service, so it stays current.
The slide keeps the week ahead, the daylight band and the solar forecast.

**It says how old it is.** The conditions line reads

```
Partly cloudy · 63 min old
```

and the solar panel's header reads `kWh/m² of sun · 63 min old`. A
forecast shown as if it were live would be worse than an honest error,
so it is never shown as if it were live.

**Past six hours, it is not shown at all.** A forecast does not move much
in six hours — tomorrow is still tomorrow, and the week ahead is still the
week ahead — but the conditions in it are six hours old, and after that
the forecast has drifted too far to be worth showing. Then the slide says
there is no forecast, as it did before.

**A busy service is not hammered.** After a failure the next attempt is a
minute away rather than a quarter of an hour, and the gap doubles each
time it fails, up to the usual fifteen minutes. So a service under load
is asked again soon, and then less and less often.

## How it was checked

- **End to end, with the service actually broken.** The server was run
  with the fetch replaced by one that always raises
  `HTTP 503: {"error":true,"reason":"The service is overloaded"}`, and
  the cache seeded with a real reply:

  ```
  error:       None
  stale:       True  age: 3801 s = 63 min
  stale_error: WeatherError: HTTP 503: {"error":true,"reason":"The service is overloaded"}
  days:        7
  current:     11.0 Partly cloudy
  updated:     1793626600.011445     <- when it was fetched, not when it was used
  ```

- **The layout sweep, with the stale payload**, at ten viewport sizes,
  three slides and two diagram styles: the marker fits at every one of
  them, and no header grows a line. The conditions line and the solar
  panel's header are the two places it appears, because they are the two
  that fit everywhere — the panel's hint is one line and ellipsised, and
  the attribution is the credit the service asks for and is left alone.
- **Twenty-three new tests**, covering the cache (it survives a restart, a
  broken file is nothing, a file of another version is nothing, it is
  0600, it is kept next to the settings, the demo writes nothing), the
  fallback (the forecast is kept, the age is right, the reason is kept,
  a six-hour-old cache is not used, a failure with no cache is still the
  error, the reply is kept for next time, a busy service is asked again
  sooner — even when the old forecast is the one being shown), and the
  marker on the slide.

## Testing

- 524 tests (was 501): twenty-three for the weather cache. All of them
  pass.
